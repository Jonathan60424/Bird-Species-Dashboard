# Bird Species Observation Analysis Dashboard

Analyzes bird observations across forest and grassland habitats in
National Park Service units, built for the same style of project as the
earlier movie dashboard — data cleaning → SQLite → Streamlit + Plotly.

## Project structure

```
bird_dashboard/
├── data/
│   ├── sample_bird_data.xlsx      # synthetic placeholder data (4 sheets)
│   ├── cleaned_bird_data.csv      # output of the cleaning script
│   └── bird_observations.db       # SQLite db the app reads from
├── scripts/
│   ├── generate_sample_data.py    # makes the synthetic placeholder workbook
│   └── 01_clean_data.py           # cleans + consolidates + loads SQLite
├── app.py                         # Streamlit dashboard
└── requirements.txt
```

## Setup

```bash
pip install -r requirements.txt
```

## Using your real dataset

1. Download the Excel workbook from the project's Drive link (multi-sheet,
   one sheet per Admin_Unit_Code: ANTI, CATO, CHOH, GWMP, HAFE, MANA, MONO,
   NACE, PRWI, ROCR, WOTR).
2. Put it in `data/`, e.g. `data/Bird_Observation_DataSet.xlsx`.
3. Run the cleaning pipeline pointed at it:

   ```bash
   python scripts/01_clean_data.py --input data/Bird_Observation_DataSet.xlsx
   ```

   This regenerates `data/cleaned_bird_data.csv` and
   `data/bird_observations.db` from your real data — no other changes
   needed, the dashboard reads from the db either way.

4. Launch the dashboard:

   ```bash
   streamlit run app.py
   ```

## What the cleaning script does

- Reads every sheet in the workbook and stacks them into one table,
  tagging rows with `Admin_Unit_Code` from the sheet name if it's missing.
- Strips whitespace, drops exact duplicate rows.
- Parses `Date`, derives `Month` and `Season`.
- Normalizes boolean-ish columns (`TRUE`/`FALSE`/`1`/`0`/etc.) into real booleans.
- Coerces numeric columns (`Temperature`, `Humidity`, counts).
- Fills missing categorical fields (`Sex`, `Sky`, `Wind`, `Disturbance`,
  `ID_Method`) with `"Unknown"` rather than dropping rows.
- Drops rows with no species identification (unusable for species analysis).
- Flags (doesn't drop) implausible temperature/humidity values via
  `Temperature_Outlier` / `Humidity_Outlier` columns, so you can decide
  how to handle them.
- Writes both a CSV (for inspection) and a SQLite database with indexes
  on the columns you'll filter/group by most (admin unit, habitat, species, year).

## Dashboard sections

Sidebar filters (admin unit, habitat, year, species, watchlist-only) apply
across all tabs:

| Tab | Covers |
|---|---|
| Temporal | Yearly/seasonal trends, year×month heatmap |
| Spatial | Habitat comparison, admin unit totals, plot-level species richness |
| Species | Most-observed species, ID method, sex ratio, diversity by habitat |
| Environmental | Temperature/humidity vs. bird count, sky condition, disturbance |
| Distance & Behavior | Observation distance bands, flyover vs. non-flyover |
| Observers | Observations per observer, diversity by visit number |
| Conservation | Top PIF watchlist species, regional stewardship status, filterable watchlist table |

## Notes

- `data/sample_bird_data.xlsx` is **synthetic placeholder data** (4 fake
  park sheets, 12 made-up species) generated by
  `scripts/generate_sample_data.py` purely so the pipeline and dashboard
  could be built and verified before the real dataset was available.
  Delete it once you're running on real data — it's not analysis output.
- Column definitions match the project brief exactly (29 source columns);
  see the brief for full descriptions of each.
